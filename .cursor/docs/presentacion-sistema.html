Visión

¿Qué es Transtemare?

Aplicación para administrar el ciclo de vida de carpetas de transporte internacional: datos de empresas, transportadoras, flota, terminales y generación de documentación aduanera (CRT, MIC/MICDTA y derivados).

Funcional

Propuesta de valor

Una carpeta, todo el viaje

Centraliza remitente, destinatario, ruta, camión, chofer, contenedor y garantías en un solo expediente.

Documentación oficial

Emite PDF de CRT, MICDTA (y variantes con camión sustituto), sabana y carátula desde JasperReports.

Maestros operativos

ABM de empresas, transportadoras, camiones/remolques y terminales que alimentan las carpetas.

Transporte internacional Aduana / CRT MIC / MICDTA Histórico de carpetas

Dominio

La carpeta como entidad central

CRT vs MIC

  • CRT (esCRT=true): documento principal / carpeta padre.
  • MIC/MICDTA (esCRT=false): documentos subsidiarios vinculados (cantidadMic).
  • La transportadora aporta prefijo, numeradores y logo.

Datos que componen una carpeta

  • Empresas tipadas: remitente, destinatario, consignatario, cliente, despachante, agencia.
  • Camión / remolque / chofer (original + sustituto).
  • Rutas, aduanas, localidades, países, terminal.
  • Contenedor (SUELTA, 20, 40, LASTRE) y garantía.

Técnico

Arquitectura del monorepo

Tres módulos: dominio/persistencia (core), WAR Struts (web) y SPA React en migración. No hay API REST moderna: React consume las mismas acciones Struts del legacy.

Monorepo

Módulos

transtemare-core

JAR Maven · Java 1.6

  • Entidades / DTOs / enums
  • DAOs + RowMappers
  • SQL constants
  • Fachadas de negocio

transtemare-web

WAR · Struts 2 + Spring

  • Actions + interceptors
  • JSP legacy
  • JasperReports
  • Spring JDBC / c3p0

transtemare-react

SPA Vite · React 19

  • MUI 7 + DataGrid
  • TanStack Query
  • Proxy /api → WAR
  • Sesión por cookie
tramstemare/
├── transtemare-core/   # dominio + persistencia
├── transtemare-web/    # Struts UI/API + reportes
└── transtemare-react/  # SPA de migración

Regla de oro

Action → Fachada → DAO → SQL. Nunca SQL en actions. Nuevas actions se registran como beans Spring en applicationContext.xml.

Integración

React ↔ Struts

HTTP

  • baseURL: '/api'
  • withCredentials: true
  • Content-Type form-urlencoded
  • ABM: oper=add|edit|del, id=_empty|<id>

Auth

  • Login POST /entrar
  • Probe GET /jsonEmpresas?rows=1&page=1
  • Logout GET /logout
  • Cookie JSESSIONID (rewrite en Vite)

Importante

No hay capa REST nueva. La SPA es un cliente del mismo contrato que usaban jqGrid y los JSP. Algunas respuestas siguen siendo HTML (éxito inferido por contenido).

Migración

Estrategia strangler

1. Reusar backend

Identificar actions existentes y tiparlas en TypeScript.

2. Envolver en api/

Un módulo por dominio con el client axios compartido.

3. Pantalla React

Seguir patrón CRUD o form legacy; registrar ruta + nav.

Local

Cómo levantarlo

Backend

cd transtemare-core
mvn clean install

cd ../transtemare-web
mvn clean package
# desplegar WAR en :8080

DB: MySQL skuncadb · contexto /transtemare-web

Frontend

cd transtemare-react
npm install
npm run dev
# http://localhost:3000

Proxy /api → localhost:8080/transtemare-web

Resumen

En una frase

Funcional

Gestiona carpetas de transporte internacional y emite la documentación CRT/MICDTA a partir de maestros operativos.

Técnico

Monorepo Java Struts + Spring JDBC + MySQL, con SPA React que consume las acciones legacy vía proxy y sesión cookie.

Dirección

Migración gradual JSP → React sin reescribir el backend; Carpetas es la frontera actual.
